# 8bitnews — архитектура

Статус: черновик v0.1 (2026-10-24). Источник правды для людей и агентов PolyMaths.
Решения, помеченные **[решено]**, согласованы; **[предложение]** — обсуждается в своём эпике.

## 1. Что строим

Фабрику коротких аналитических новостных роликов (вертикальное видео, 45–90 с) для нескольких стран,
на языке страны. Старт — US и ES. Площадки — YouTube Shorts, TikTok, Instagram Reels.

RU не делаем **[решено]**: независимая аналитика там упирается либо в государственную повестку, либо в статус иноагента.

Ролик — не пересказ новости, а аналитический обзор ситуации:

> На текущий момент известно вот это (факты с источниками). Мнения внутри страны делятся на такие группы.
> В мировой прессе — такие кластеры. Неизвестно пока вот это.

## 2. Принципы

1. **Страна и канал — данные, а не код.** Новая страна = профили в `channels/` и `countries/` + аккаунты + расписание. **[решено]**
2. **Формат описывается на уровне канала.** Канал = страна + язык + площадки + формат + шаблоны. **[решено]**
3. **Генерацию делают команды агентов PolyMaths** (проект `8bitnews`). Детерминированную обвязку —
   хранение, модерацию, публикацию, статистику, эксперименты — делает Go-сервис **hub**. **[решено]**
4. **Каждый факт прослеживается до источника.** Нет источника — нет утверждения в ролике.
5. **Публикация — только после одобрения человеком** на старте; флаг `moderation.approval_required` на канале. **[решено]**
6. **Эксперименты — опция канала.** Вариант ролика назначает hub (рандомизация), а не LLM.
7. **Метрики всех площадок — в одной БД**, дашборды — DataLens поверх неё. **[решено]**

## 3. Общая схема

```
 PolyMaths, проект 8bitnews                                   hub (Go)                      площадки
 ─────────────────────────────────────────────                ───────────────────────       ─────────
 cron канала ─► Newsroom ──делегирует──► Research             MCP + REST API
                   │      ──делегирует──► Script              Postgres  ◄──────────────┐
                   │      ──делегирует──► Video ──► S3        Telegram-модерация       │
                   │      ──делегирует──► QA                  Publisher ──────────────►│ YouTube
                   └──── release_submit (MCP) ───────────────►Stats collector ◄────────│ TikTok
                                                                  │                    │ Instagram
                                                                  ▼
                                                              DataLens
```

## 4. Конвейер одного ролика

| # | Стадия | Кто | Выход |
|---|---|---|---|
| 1 | Отбор сюжета | Newsroom / `editor` | `story_brief` |
| 2 | Назначение варианта | hub, `experiment_assign` | параметры варианта внутри `story_brief` |
| 3 | Ресерч: факты, локальная пресса, мировая пресса, обзор | Research | `research_dossier` |
| 4 | Сценарий | Script | `script` |
| 5 | Ролик: озвучка, визуал, рендер, субтитры, обложка | Video | `video_package` (файлы в S3) |
| 6 | Автовалидация | QA | `validation_report` (pass / fail) |
| 7 | Сдача в hub | Newsroom / `editor` | `release_receipt` |
| 8 | Модерация | hub + человек в Telegram | approved / rejected / changes_requested |
| 9 | Публикация | hub publisher | публикации на площадках |
| 10 | Сбор статистики | hub collector | снимки метрик → DataLens |

Возвраты:
- QA `fail` → роутер Newsroom возвращает работу в Script или Video с замечаниями (не больше двух кругов), дальше `needs_human`.
- Модератор нажал «Доработать» → hub отправляет `task_feedback` в задачу Newsroom с текстом модератора.
- Модератор нажал «Отклонить» → причина пишется в hub (это тоже данные для анализа качества).

Один запуск расписания = один сюжет = один ролик. Один ролик публикуется на все включённые площадки канала
с метаданными под каждую площадку.

## 5. Команды PolyMaths

Команды общие для всех каналов: всё, что зависит от канала, агенты берут из профиля канала (`channel_get` в hub
или файлы `channels/<id>/` в репозитории). Промпты агентов и JSON-схемы контрактов хранятся в `newsroom/`
и синхронизируются в PolyMaths — источник правды репозиторий. Все задачи контент-конвейера идут
с `work_intent: explanation` (без кода и PR).

### Newsroom (тип `other`) — точка входа
Запускается расписанием, по одному на канал.
- `router` — ведёт задачу строго по стадиям 1 → 3 → 4 → 5 → 6 → 7, делегируя командам.
- `editor` — сканирует источники страны за последние N часов, отбирает сюжет под редполитику канала,
  проверяет дубли (`story_find_similar`), регистрирует сюжет и получает вариант (`experiment_assign`),
  пишет `story_brief`. В конце собирает пакет и вызывает `release_submit`.
- Контракты: `story_brief`, `release_receipt`.

### Research (тип `research`) — принимает делегирование
- `fact_researcher` → `facts_report`: факты со статусом (confirmed / disputed / unverified / false), первоисточник
  или минимум два независимых источника для confirmed, хронология, что пока неизвестно.
- `local_press_analyst` → `local_press_report`: пресса страны по всему спектру, группы мнений, представители, цитаты, опросы.
- `world_press_analyst` → `world_press_report`: мировая пресса, кластеры мнений по регионам, чем отличаются от внутренних.
- `analyst` → `research_dossier`: сводит три отчёта и пишет аналитический обзор: известно / мнения в стране /
  мнения в мире / неизвестно, со ссылками на `F*`, `L*`, `W*`.
- `fact_checker` (reviewer) — каждое утверждение обзора сводится к элементу досье; выборочно открывает источники;
  мнения атрибутированы; нет оценок от лица канала.
- Первые три агента роутер запускает параллельно.
- Рабочий язык досье — английский; обзор (`review`) — на языке канала. **[предложение]**
- Промпты: `newsroom/teams/research/`, контракты: `newsroom/contracts/`.

### Script (тип `smm`) — принимает делегирование
- `scriptwriter` — сценарий по `channels/<id>/format.md` и параметрам варианта: хук, сцены (текст диктора,
  текст на экране, визуальная подсказка, ссылки на `fact_id`), тайминг; заголовки, описания и хэштеги под каждую площадку.
- `script_editor` (reviewer) — верность досье, длительность, язык носителя, правила канала.
- Контракт: `script`.

### Video (тип `other`) — принимает делегирование
- `video_producer` — работает студийным тулкитом репозитория (`studio/`): TTS → ассеты → рендер шаблона →
  субтитры → обложка → техническая самопроверка → загрузка в S3.
- Контракт: `video_package`.

### QA (тип `qa`) — принимает делегирование
- `tech_validator` — детерминированные проверки (`studio validate`, см. §8).
- `content_validator` — транскрипт озвучки и текст в кадре против досье и сценария.
- `policy_validator` — правила страны и площадок (профиль канала), раскрытие AI-контента, права на визуал.
- Контракт: `validation_report`.

### Доступы агентов
- hub подключается к проекту как MCP-сервер (заголовок с `${secret:HUB_API_KEY}`).
- Веб-поиск и загрузка страниц — встроенные инструменты агентов.
- Ключи S3, TTS, генерации изображений — секреты проекта PolyMaths.

### Разработка
Код hub, студийного тулкита и прочего пишет стандартная **Development Team** проекта (PR в этот репозиторий).
Контент-команды кода не пишут.

## 6. hub (Go)

Один бинарник, несколько ролей (`hub serve`, `hub worker`), Postgres, S3, docker compose для локальной разработки.

| Компонент | Что делает |
|---|---|
| `api` | REST и MCP (streamable HTTP) для агентов: `channel_get`, `story_find_similar`, `story_register`, `experiment_assign`, `release_submit`, `release_get` |
| `moderation` | Telegram-бот: превью ролика, сводка, отчёт валидации, кнопки «Опубликовать» / «Отклонить» / «Доработать» |
| `publisher` | Адаптеры YouTube / TikTok / Instagram; слоты публикации в часовом поясе канала; идемпотентность, ретраи; флаги раскрытия AI-контента |
| `collector` | Снимки метрик каждой публикации на возрастах 1ч, 3ч, 6ч, 24ч, 48ч, 7д, 30д и далее ежедневно |
| `experiments` | Эксперименты, руки, назначение (uniform → Thompson sampling), закрепление варианта за роликом |
| `polymaths` | Клиент API PolyMaths: `task_feedback` при «Доработать», ссылки на задачи |

Адаптер площадки — один интерфейс на публикацию, статус и метрики, чтобы новая площадка (например, VK Клипы)
добавлялась без изменений остального кода.

Заметки по площадкам (сверить с актуальной документацией в начале эпика):
- **YouTube Data API v3** — дневная квота по умолчанию ≈ 6 загрузок на GCP-проект; нужна заявка на увеличение.
  Метрики — YouTube Analytics API. Флаг синтетического контента — в `status` видео.
- **TikTok Content Posting API** — без пройденного аудита приложения публикация только приватная.
  Загрузка с URL требует подтверждения домена; надёжнее загрузка файла. Флаг AI-контента есть в API.
- **Instagram Graph API** — Business/Creator-аккаунт, привязанный к странице Facebook; Reels публикуются
  через контейнер по публичному URL видео (подойдёт presigned URL S3). Метрики — Insights.

## 7. Данные (Postgres)

| Таблица | Суть |
|---|---|
| `countries`, `channels` | Синхронизируются из `countries/` и `channels/` репозитория |
| `platform_accounts` | Аккаунт канала на площадке, OAuth-токены (шифрованы) |
| `stories` | Сюжет: канал, заголовок, суть, ключ/эмбеддинг для дедупликации, ссылка на задачу PolyMaths |
| `releases` | Пакет к публикации: сюжет, вариант, статус, медиа в S3, JSON досье / сценария / отчёта валидации |
| `experiments`, `experiment_arms`, `assignments` | Эксперименты и назначение вариантов |
| `publications` | Ролик на площадке: аккаунт, внешний id, URL, время, статус |
| `metric_snapshots` | Временной ряд: `captured_at`, `age_minutes`, просмотры, лайки, комментарии, репосты, сохранения, время просмотра, средний % досмотра, прирост подписчиков, `raw jsonb` |
| `events` | Журнал: модерация, публикации, ошибки |

Статусы релиза: `submitted → pending_approval → approved → scheduled → published`,
ветки `rejected`, `changes_requested`, `failed`.

Для DataLens — набор SQL-представлений (`analytics/datalens/`): сводка по каналам и площадкам, карточка ролика,
кривые набора просмотров по возрасту, сравнение рук экспериментов, здоровье конвейера (время от сюжета до публикации,
доля отклонённых, причины падения валидации).

## 8. Валидация

Три слоя; любой блокер → `fail`.

1. **Технический** (детерминированный, `studio validate`): 1080×1920 (9:16), 30 fps, H.264 + AAC, длительность в
   диапазоне канала, громкость около −14 LUFS, нет пауз тишины длиннее порога, субтитры есть и в синхроне,
   текст в безопасных зонах интерфейса площадок, размер файла. hub повторяет дешёвые проверки при приёме релиза.
2. **Содержательный** (LLM против досье): каждое утверждение в озвучке и в кадре сводится к факту досье с источниками;
   мнения атрибутированы; нет утверждений, которых нет в досье; ролик соответствует сценарию.
3. **Политики**: правила страны (`countries/<cc>/policy.md`) и площадок, раскрытие AI-контента, права на визуал
   (никаких чужих фото из прессы — только сгенерированное, стоки с лицензией, собственная инфографика).

## 9. Эксперименты (опция канала)

Одну и ту же новость нельзя выложить в двух вариантах на один канал: дубли режут площадки, и варианты
конкурируют за одну аудиторию. Поэтому **единица рандомизации — ролик**: каждый новый ролик получает руку
эксперимента, а сравниваются руки на множестве роликов.

- Эксперимент: канал(ы), фактор (шаблон, тип хука, голос, длительность, стиль заголовка, обложка, слот публикации),
  руки с параметрами, способ распределения (равномерно → Thompson sampling), главная метрика
  (например, средний % досмотра на 24ч или log просмотров на 24ч), минимальная выборка, статус.
- На старте — один активный фактор на канал; позже — несколько факторов одновременно.
- Параметры руки приезжают в `story_brief`, Script и Video обязаны их соблюдать; QA проверяет соответствие.
- Эксперименты выключены → всегда рука по умолчанию из профиля канала.

## 10. Профиль канала

`channels/<id>/channel.yaml` — параметры (пример: `channels/8bitnews-us/channel.yaml`),
`channels/<id>/format.md` — формат словами для сценариста и продюсера: стиль, структура, голос, примеры.

Профиль страны — `countries/<cc>/`: `sources.yaml` (локальная пресса с пометкой позиции в спектре,
мировая пресса по регионам, агентства) и `policy.md` (правовые и редакционные ограничения).

## 11. Масштабирование

- **Новая страна / канал** — профили в репозитории, аккаунты в hub, расписание в PolyMaths. Кода нет.
- **Новый формат** — шаблон в `studio/templates/<id>` + ссылка в профиле канала.
- **Новая площадка** — адаптер в hub.
- **Пропускная способность** — лимиты команд PolyMaths и лимиты подписки LLM. Ролик ≈ 1 корневая + 4 делегированные
  задачи ≈ 8–12 прогонов агентов; стартуем с 1–3 роликов в день на канал и смотрим на расход.

## 12. Структура репозитория

Go-модуль `github.com/tereshed/8bitnews`. Каталоги создаются по мере эпиков — ниже то, что есть
после E0, и (помечено **[план]**) то, что добавят следующие эпики.

```
docs/                             архитектура, решения
channels/<id>/                    профили каналов (данные)
  channel.schema.json             JSON Schema (draft 2020-12) для channel.yaml
countries/<cc>/                   источники и политики стран (данные)
  sources.schema.json             JSON Schema (draft 2020-12) для sources.yaml
newsroom/                         промпты агентов и JSON-схемы контрактов (синхронизируются в PolyMaths)
cmd/profiles/                     CLI: `go run ./cmd/profiles validate [--strict]`
internal/profile/                 загрузка и валидация профилей каналов и стран
deploy/                           docker-compose.yml (Postgres для локальной разработки)
.github/workflows/                CI: lint, test, validate-profiles
studio/                           [план, E2] тулкит генерации ролика: TTS, ассеты, шаблоны, рендер, validate
  templates/<id>/
cmd/hub/                          [план, E1] Go: точка входа hub
internal/{api,mcp,moderation,…}   [план, E1] api, mcp, moderation, publisher, collector, experiments, store
migrations/                       [план, E1] SQL-миграции
analytics/datalens/               [план, E5] SQL-представления и описание дашбордов
```

Движок рендера шаблонов — **[предложение]** Remotion (React-шаблоны → mp4, богатая анимация, удобно размножать
шаблоны под эксперименты; для компаний больше трёх человек нужна платная лицензия). Альтернатива — ffmpeg-пайплайн.
Решается в эпике E2.

## 13. Роадмап (эпики автопилота)

| Эпик | Содержание | Кто |
|---|---|---|
| E0. Фундамент | Go-модуль, структура, CI (lint, test), docker compose (Postgres), схема и валидатор профилей каналов | Dev Team |
| E1. hub: ядро | Миграции, REST, MCP для агентов, S3, деплой | Dev Team |

| E3. Контент-команды | Newsroom / Research / Script / Video / QA: промпты и контракты в `newsroom/`, настройка в PolyMaths, прогон end-to-end для 8BitNewsUS по ручному запуску | конфигурация + Dev Team |
| E4. Модерация и публикация | Telegram-модерация, YouTube → TikTok → Instagram | Dev Team |

приложения и доступы к API (GCP-проект + квота YouTube, приложение TikTok + аудит, приложение Meta + Instagram Business),
бакет S3, хостинг hub, Telegram-бот модерации, ключи TTS и генерации изображений.

## 14. Риски

- **Доступы к API площадок** — аудит TikTok и квота YouTube занимают недели; начинать сразу.
- **Права на визуал** — фото из прессы не используем.
- **Раскрытие AI-контента** — обязательно на всех площадках.
- **Стоимость и пропускная способность** — см. §11.

## 15. Открытые вопросы

- Провайдеры TTS и генерации изображений.
- Частота роликов на канал и слоты публикации.
